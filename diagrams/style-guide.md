# VideoMesh Diagram Style Guide

**Status:** shared visual system for VideoMesh V1.1 canonical diagrams.

| Role | Value | Use |
|---|---:|---|
| `paper` | `#111418` | page background |
| `paper-2` | `#181D23` | standard nodes |
| `paper-3` | `#20262E` | stores / activation |
| `ink` | `#F3F5F7` | primary text |
| `muted` | `#A7B0BB` | connectors / secondary text |
| `soft` | `#77828E` | metadata / sublabels |
| `rule` | `#2C343E` | zones / hairlines |
| `rule-solid` | `#46515E` | stronger borders |
| `accent` | `#E47A36` | VideoMesh focal role |
| `link` | `#7299C5` | SoftSight / contract boundary |
| `good` | `#7D9B7A` | satisfied gate / READY |

## Grammar

- Deep-neutral engineering canvas.
- No glow, shadows or decorative gradients.
- Required paths are solid; optional/future paths may be dashed.
- Off-axis connectors are orthogonal.
- VideoMesh uses the warm focal accent; SoftSight / shared contract boundaries use blue.
- Green is reserved for a satisfied gate or READY state, not general decoration.
- Diagrams are views, not sources of truth.
